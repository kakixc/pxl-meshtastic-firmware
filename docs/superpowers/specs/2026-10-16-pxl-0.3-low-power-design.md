# PXL Meshtastic 0.3: Heltec V3 low power design

## Goal

Build PXL 0.3 from the exact official Meshtastic tag `v2.7.26.54e0d8d`. Keep the PXL 0.2 boot animation, PXL STATUS screen, Cyrillic OLED support, and shorter stock splash. Improve battery operation on Heltec V3 using ESP32-S3 power management and dynamic light sleep while keeping the normal Meshtastic radio stack, configuration format, and regional limits. A successful build is only a prerequisite; energy savings require current measurements on a physical board.

## Chosen approach

Use the existing repository as a reproducible patch-and-build project. Its workflow clones the official tag, applies PXL patches, builds with PlatformIO, and uploads `update.bin` as a GitHub Actions artifact. The feature branch has no schedule or release-publishing job. The application image remains a normal update image; the workflow also keeps the factory image when generated, clearly distinguished from the update image.

Enable ESP-IDF power management only in the `heltec-v3` PlatformIO target. Pin a compatible Arduino 2.x framework package built with `CONFIG_PM_ENABLE` and tickless idle, then verify those flags in the installed package before compiling. M1NL's `esp_light_sleep_release_stable` branch and Meshtastic PRs #7121 and #11702 are references for wake sources, power-management locks, and subsystem coordination. Their full firmware trees are not used as the base. The first implementation stays on Arduino 2.x because Meshtastic 2.7.26 pins PlatformIO `espressif32@6.13.0` and Arduino 2.0.17; an Arduino 3.x migration would affect unrelated components.

Keep the sleep changes specific to Heltec V3 or guarded by an explicit capability flag. Enter automatic light sleep only when the current Meshtastic state permits sleep. Preserve LoRa DIO1, USER button, and required communication wake sources; leave the original behavior available when the PM-capable framework is absent. Avoid changing LoRa protocol, routing, encryption, RU region handling, or transmit-power limits.

## USER button behavior

Heltec V3 uses GPIO 0. In Meshtastic 2.7.26, `ButtonThread` uses `OneButton` to classify short and long presses, and the ordinary light-sleep path temporarily detaches the normal GPIO interrupt. In dynamic light sleep, preserve the button interrupt or reconstruct a wake press without duplicating it. Do not synthesize a click merely because a GPIO woke the MCU: a long hold and a multi-press must still be classified by the existing button logic. Test awake, screen-dark, and light-sleep states, including very short presses and release during wake-up.

## Phases and gates

1. **Baseline:** manually build Heltec V3 from the exact official tag with all PXL 0.2 UI changes. Verify the Actions workflow cannot publish a release and retains `-update.bin` packaging.
2. **PM capability:** pin and inspect a PM-capable framework, build Heltec V3, and demonstrate at runtime that PM configuration succeeds. If the framework cannot build or PM is unsupported, stop the power feature at this gate and record the evidence.
3. **Dynamic sleep and input:** port the compatible sleep mechanisms, maintain LoRa/Bluetooth operation, and fix short USER presses without changing long or multiple press actions. Compile and exercise the board.
4. **Release readiness:** compare PXL 0.2 and 0.3 on the same Heltec V3 hardware, settings, battery supply, and traffic conditions. Verify configuration retention with `update.bin`, record current and runtime measurements, list limitations, and leave publication as a separate manual decision.

## Validation and limits

Compilation checks API compatibility and firmware packaging. Device tests check button events, screen transitions, LoRa receive/transmit, Bluetooth reconnection, USB serial behavior, and update without erasing settings. Current draw must be measured with suitable hardware over representative awake, idle, sleep, receive, and transmit periods. No current or battery-life target is claimed before measurement. No other board changes behavior in PXL 0.3 unless a change is required to keep the shared build working.
